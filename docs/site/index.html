LAgent — Documentation

Local-only Python 3.12 Windows runtime

LAgent is a fully local, vision-driven automation system that plays a 2-character Lineage II party (Warlord + Prophet) without human intervention after login. It never reads client memory or injects packets — it only looks at the screen (screen capture + YOLO + OCR) and acts through simulated mouse/keyboard input shaped by a Human Simulation Layer (Bézier mouse paths, timing noise, fatigue, error injection).

Use this guide in order Start with Installation, then Preparation & Config, then Running LAgent. To validate the Epic 9 Supply Check flow, continue to Quest Mode. Once you need to grow a fresh character, see Class Leveling Flows. Come back to Training once you need to record data and produce your own models, and use Architecture as a reference map of the whole system.

What LAgent does

Each game window runs an independent perception → decision → action loop:

1. Capture (~10 FPS)
→
2. Extract ROIs
→
3. YOLO + OCR (GPU server)
→
4. FSM + policy decision
→
5. Human Simulation Layer
→
6. Simulated mouse/keyboard

A lightweight Party Bus (ZeroMQ PUB/SUB) keeps the Prophet's buff cycle and the Warlord's combat state in sync, and an Orchestrator process monitors heartbeats from both agents. The bounded Supply Check quest uses the same perception, FSM, HSL, lifecycle, and session telemetry foundations for a single-agent conversational flow.

System requirements

Python3.12 (declared in pyproject.toml)
Full runtime OSWindows — dxcam, pynput, pywin32 are Windows-native and required for live capture/input
Development / test OSmacOS and Linux can install the cross-platform subset and run the test suite (see Installation)
GPULocal NVIDIA GPU with ~8 GB VRAM (reference: GTX 1070 Ti); inference budget ~2.5–3.5 GB, training 4–6 GB (offline only, never during a live session)
NetworkLocal-only — zero cloud services, zero external data exposure (NFR-1)

Core principles worth knowing up front

  • No client modification, ever — no memory reads, no packet injection; only screen capture and OS-level input simulation.
  • One GPU owner — only the GPU Inference Server process touches CUDA; agents never load models directly.
  • Tray/UI is the sole launcher — all runtime processes (agents, GPU server, orchestrator) are spawned by python -m lagent.ui, never started standalone in normal operation.
  • Fail-fast configuration — an invalid YAML profile raises a validation error at startup; there is no silent fallback to defaults.
  • Training never runs alongside a live session — the training pipeline is a separate CLI and competes for the same GPU.
