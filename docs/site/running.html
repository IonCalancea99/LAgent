Running LAgent

LAgent is normally operated entirely through the system tray icon. This page also documents the manual per-process commands, which are useful for development and debugging.

Launching via the tray/UI (normal usage)

The Tray/UI process is the sole launcher of every other runtime process. Start it with:

python -m lagent.ui

or, after installation, the console script:

lagent-ui

No main window or taskbar entry appears — the tray icon in the notification area is the entire control surface. Left as-is, LAgent does nothing until you start a session from the tray menu.

Tray menu actions

Start Session

Submenu to pick a profile: Fishing / Combat (Warlord + Prophet) / Shadow. Spawns the Orchestrator, GPU Inference Server, and Agent process(es).

Stop Session

Signals a clean shutdown of all spawned child processes.

Recording Mode toggle

Switches capture threads to dual-write mode and activates the input listener for training-data collection.

Open Status Overlay

Shows the always-on-top per-agent status window.

Exit

Stops any active session and closes the tray application.

Manual process launch (advanced / development)

Development use only In normal operation, never start the Orchestrator, GPU Inference Server, or Agent processes directly — the Tray/UI is the designated launcher (AD-5) and manages process lifecycle, timeouts, and cleanup. Manual launches below are for debugging one component in isolation.

Each process can also be started standalone for debugging:

# GPU Inference Server — owns all YOLO/EasyOCR/CUDA calls
python -m lagent.gpu_server

# Party Orchestrator — relays party state, monitors heartbeats
python -m lagent.orchestrator [--session-id SESSION_ID]

# Agent — one process per character window
python -m lagent.agent --class warlord --window-title "Lineage II"
python -m lagent.agent --class prophet --window-title "Lineage II - 2"

Console-script equivalents installed by pyproject.toml:

lagent-gpu-server
lagent-orchestrator
lagent-agent
lagent-ui

Status overlay & monitoring

The always-on-top, semi-transparent status overlay (PyQt6, native Windows styling) shows, per agent: current FSM state label, HP% bar, MP% bar, and session timer. Toggle it from the tray menu or its hotkey. It is intentionally lightweight — no heavy rendering runs on the live session's critical path.

When the active session emits Epic 9 quest events, the overlay and tray tooltip also show the quest name, current objective, objective progress, and running/paused/complete/failed status. Failure projections include an operator-readable safe-stop reason. See Monitor quest status for examples.

Quest Mode launch status The Supply Check engine and acceptance workflow are implemented, but Quest Mode is not yet exposed as a tray profile or --class option. Follow the shadow replay validation instead of attempting to launch it from the commands above.

Stopping a session

A session ends in one of three ways:

  • Manual stop — "Stop Session" from the tray menu.
  • Session cap reached — configurable max duration (default 4–6 hours); LAgent returns both characters to a safe location, runs a final Prophet buff cycle, and waits for both characters to be idle before halting input — even mid-combat-cycle.
  • Health failure — if the Orchestrator misses a configurable number of consecutive heartbeats (default 3) from either agent, the session halts and the failure is logged and surfaced on next launch.
