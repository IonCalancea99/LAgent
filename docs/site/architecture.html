Architecture

LAgent follows an actor model with a pipes-and-filters inner loop: every runtime entity is an autonomous OS process with no shared memory, and all cross-process coupling goes through ZeroMQ messages.

Processes at a glance

⇅
Prophet Agent

Tray/UI spawns and terminates every other process. Agents exchange party state directly (PUB/SUB); the Orchestrator only observes heartbeats and relays party events.

ProcessResponsibility
Tray / UI (lagent.ui)Sole process launcher; system tray + status overlay; never imports agent/hsl/gpu_server modules
Warlord / Prophet Agent (lagent.agent)Owns capture → inference-request → FSM/policy → HSL → OS input for one character window
GPU Inference Server (lagent.gpu_server)Sole owner of all YOLO + EasyOCR + CUDA calls; serves both agents over DEALER/ROUTER
Party Orchestrator (lagent.orchestrator)Relays Party Bus state between agents, monitors heartbeats, triggers session halt on health failure
Training Pipeline (lagent.train, offline CLI)Record → prelabel → train → atomic deploy; never runs concurrently with a live session

Per-agent inner loop (pipes-and-filters)

Capture thread (~10 FPS)
→
ROI extraction
→
GPU inference request (DEALER)
→
PerceptionResult
→
FSM + BC policy
→
Human Simulation Layer
→
Simulated OS input

Every bounded internal queue (capture→inference, inference→policy) uses oldest-frame eviction with a max depth of 2 frames per stage — a slow GPU tick never blocks the capture thread.

Key architectural invariants

Condensed from the project's Architecture Spine (AD-1…AD-13):

IDRule
AD-1All cross-process communication is ZeroMQ; no shared memory, no filesystem polling
AD-2Only the GPU Inference Server loads models or issues CUDA calls
AD-3Internal queues use oldest-frame eviction; capture thread never blocks
AD-4Each Agent owns its own GameState; only the PartyState subset crosses process boundaries
AD-5Tray/UI is the sole launcher of every runtime child process
AD-6Training Pipeline is a separate CLI; never co-runs with a live session
AD-7Model versioning via atomic current.pt path swap; loaded at server startup only
AD-8HSL is a per-agent instance (fatigue/timing state never global); Shadow Mode lives inside HSL
AD-9Single WAL-mode SQLite sessions.db; one connection per process
AD-10OCR runs only in the GPU Inference Server; agents never touch pixels directly
AD-10bAll spatial/proximity math uses frame-pixel coordinates — no game-world coordinate system
AD-11Fixed ZeroMQ patterns: Agent↔GPU is DEALER/ROUTER, Party Bus is PUB/SUB; no REQ/REP anywhere
AD-12lagent.common is the only shared import; processes never import each other
AD-13Recording Mode (--record) is mutually exclusive with live Session Mode at process launch

Allowed import graph

lagent.common  →  lagent.hsl     →  lagent.agent (warlord / prophet)
lagent.common  →  lagent.agent
lagent.common  →  lagent.gpu_server
lagent.common  →  lagent.train      (types only)
lagent.common  →  lagent.ui

lagent.common holds every shared type: GameState, PartyState, PerceptionResult, Action, AgentProfile. No module may add a reverse or cross edge to this graph.
