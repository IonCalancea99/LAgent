Combat Mode

Epic 6 Warlord + Prophet

Combat Mode launches one Agent per game window. Startup selects the concrete FSM from --class; an unknown class fails instead of falling back to an idle policy.

Warlord combat FSM

IDLE

PULLING
→
FIGHTING

LOOTING
→
IDLE

Mob evidence starts a pull, center-frame proximity starts the AoE rotation, and a clear mob area opens the bounded loot window. Every action passes through HSL and each transition is appended to the shared session database.

Prophet buff FSM

IDLE + independent timers
→
BUFFING
→
Safety Check
→
Cast or bounded retry

The Prophet projects current HP/MP OCR, detections, and the latest fresh Warlord PartyState into its local GameState. A nearby mob or Warlord PULLING state defers the cast without dropping the pending buff.

Lifecycle interruptions

SignalStateBehavior
Death evidenceDEADSuppress combat, execute configured recovery actions, then resume the prior state.
Inventory fullRETURNINGSuspend combat, execute configured return and loot disposition rules, then resume from IDLE.
Session haltPAUSEDDrain queued work and emit no OS input until an operator-authorized resume.
Session capSTOPPEDWarlord stops action selection idempotently; Prophet suppresses casts after observing the stopped party state.

Profile controls

profiles/warlord.yaml defines pull, AoE, loot, recovery, inventory, and timing bindings. profiles/prophet.yaml defines buff durations, cast keys, safety radius, and retry cadence. Invalid profiles fail at startup.
