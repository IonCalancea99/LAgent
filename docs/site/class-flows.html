Class Leveling Flows

A class flow is the ordered instruction set that grows a fresh character from creation through its early professions and gate quests until it is ready to hand off to a standing farming profile such as warlord.yaml or prophet.yaml. This page covers the anatomy of a flow, how to author a new one, a worked example, and how to recover when a flow drifts off course.

Not the same as the Training Pipeline Training Pipeline trains the YOLO vision models the agent sees with. A class flow is about training (leveling) a character — the two are unrelated and can be worked on independently.
Quest steps still need a human in the loop LAgent has no dialogue-parsing or quest-scripting engine today. A class flow's grind phases can run under the same FSM/profile machinery as regular farming, but profession changes and gate-quest turn-ins should be treated as supervised checkpoints — run them in Shadow Mode or handle the dialogue yourself, then let the agent resume the grind once the checkpoint is confirmed.

Anatomy of a class flow

A flow is a short list of milestones. Each milestone bundles a level target with the goals, prep work, and verification needed before the next one starts:

Grind to target level
→
Run milestone goal(s)
→
Verify completion
→
Prep for next milestone
FieldPurpose
target_levelCharacter level that closes out this milestone
grind_profileWhich existing combat/support profile (and mob area override) drives XP gain for this level range
goalsWhat else must happen at this milestone — e.g. a profession change, a gate quest, a stat/skill allocation
verifyHow completion is confirmed — OCR of the level/class label, an inventory check, a quest-tracker read
prep_checklistWhat must be true before the next milestone can safely start — items, adena, location, NPC access
on_failWhat to do if verify doesn't pass — retry, pause and alert, or fall back to a safer grind loop

Adding a new class flow, step by step

  1. Map the milestones first, on paper. List every level target, profession change, and gate quest in order before writing any config — this is the cheapest place to catch a wrong sequence.
  2. Author the flow file alongside the existing profiles, e.g. profiles/flows/<class>.flow.yaml, using the milestone fields above.
  3. Reuse an existing combat profile for each grind phase. Point grind_profile at a copy of warlord.yaml or prophet.yaml with ROIs and mob_area tuned to the level-appropriate hunting zone — don't reinvent FSM bindings per milestone.
  4. Write each gate quest as an explicit, supervised checklist (NPC, location, items to turn in) rather than an automated action script, per the caveat above.
  5. Define verify before you define prep_checklist. If you can't state how the agent (or you) will know the milestone is done, the milestone is too vague.
  6. Dry-run the whole flow in Shadow Mode before letting it run unattended, and again after any change to a milestone.
  7. Define the handoff. State explicitly which standing profile takes over once the flow's last milestone is verified, so the character doesn't sit idle in a flow that has nothing left to do.

Worked example — Destroyer to level 28, first profession, level 29 prep

A flow to take a fresh Destroyer from creation through its first profession and stage it for the level 29 laboratory gate:

MilestoneTarget levelGoalsVerifyPrep for next
A — Early grind 20 Grind on grind_profile: destroyer_low in a level-appropriate zone; complete the first-profession quest chain Character sheet shows the post-profession class name and level ≥ 20 Confirm skill bar reflects the new profession's key bindings before resuming the grind
B — Mid grind 28 Continue grinding on the same profile, widening mob_area/hunting zone as level rises Level reads 28 for two consecutive status checks (avoids acting on a stale OCR read) Build the level 29 laboratory prep checklist below
C — Laboratory prep (at 28) 28 (gate) Gather required quest materials, reserve adena for the laboratory fee, travel to the laboratory NPC, save a checkpoint Inventory check confirms materials + adena reserve; agent is stationed at the laboratory NPC Hand off to the level 29 laboratory milestone/flow segment once the character actually hits 29

Sketch of the flow file for the example above:

name: destroyer_leveling
handoff_profile: warlord   # profile to switch to once this flow's milestones are done
milestones:
  - id: first_profession
    target_level: 20
    grind_profile: profiles/flows/destroyer_low.yaml
    goals: ["first_profession_quest"]
    verify: {type: class_label_ocr, expect: "Destroyer"}
    prep_checklist: ["confirm skill_key_bindings updated for new profession"]

  - id: grind_to_28
    target_level: 28
    grind_profile: profiles/flows/destroyer_low.yaml
    goals: []
    verify: {type: level_ocr, expect: 28, confirmations_required: 2}
    prep_checklist:
      - "gather laboratory quest materials"
      - "reserve adena for laboratory fee"
      - "travel to laboratory NPC"

  - id: laboratory_29_gate
    target_level: 28
    goals: ["laboratory_prep"]
    verify: {type: inventory_check, items: ["lab_material_a", "lab_material_b"], min_adena: 50000}
    on_fail: {action: pause_and_alert}
    prep_checklist: ["hand off to level_29 flow segment once level reads 29"]
Keep the gate as its own milestone Treating the level 29 laboratory prep as a distinct milestone (rather than folding it into the grind-to-28 milestone) makes it trivial to pause right before the gate for a supervised turn-in, without touching the grind logic above it.

Generic class flow template

Copy this skeleton for any new class and fill in the blanks:

name: <class>_leveling
handoff_profile: <standing profile to switch to once done>
milestones:
  - id: <short_id>
    target_level: <level>
    grind_profile: <path to a profile tuned for this level range>
    goals: [<profession change, gate quest, stat allocation, ...>]
    verify: {type: <class_label_ocr|level_ocr|inventory_check|...>, ...}
    prep_checklist: [<what must be true before the next milestone>]
    on_fail: {action: <retry|pause_and_alert|fallback_grind>}
  # repeat one block per milestone, in level order

Rectifying a flow that's going wrong

Signals a flow has drifted off course:

  • Level or session time climbing with no matching goal progress (stuck on a grind loop past its milestone)
  • Repeated deaths or returns-to-town in the same spot
  • The FSM sitting in one state far longer than fsm_bindings timeouts suggest it should
  • A verify check failing over and over (e.g. OCR never reads the expected class/level)
  • The agent acting on the wrong skill bar after a profession change

Diagnose before changing anything:

  1. Check the Status Overlay for current FSM state, HP/MP, and elapsed time.
  2. Query recent rows in data/sessions.db's events table for the session to see the actual state/transition history.
  3. If it was recorded, review the footage under recordings/ for the exact moment things went wrong.
  4. Reproduce the same milestone in Shadow Mode to confirm the fix before trusting it unattended.
SymptomLikely causeFix
Stuck grinding past the milestone's target levelverify condition never matches (bad OCR ROI, wrong expected string)Re-check the ROI/expected value against a fresh screenshot; widen the confidence threshold if OCR is marginal
Agent dies repeatedly in the same spotgrind_profile's mob area/level range is too aggressive for the current levelNarrow mob_area or point at an easier hunting zone for that milestone
Wrong skill firing after a profession changeskill_key_bindings weren't updated for the new profession's skill barUpdate the grind profile's bindings as part of that milestone's prep_checklist
Agent idles at the gate quest indefinitelyA quest/profession goal was left for automated handling with no engine to do itTreat the goal as a supervised checkpoint per the caveat above; resume the flow once you've completed it manually
Milestone marked complete too earlyverify accepted a stale or noisy single readRequire multiple consecutive confirmations before accepting completion (see confirmations_required in the example above)
Stop before you patch Use the tray's Stop Session before editing a flow or profile file that's mid-run — never hot-edit a YAML file a running process may re-read.

More class flows worth authoring first

Fighter → tank/support lane

Level 1–20 grind, first profession into a tanking archetype, prep checklist for pairing with a support caster once it joins a party.

Mystic → support caster

Level 1–20 grind, first profession into a buff/heal-oriented class, prep checklist for feeding into an existing buff rotation such as the Prophet's.

Crafting-oriented fighter

Same level-1–20 shape, but the prep checklist swaps quest items for recipes and raw materials — useful for validating that prep_checklist generalizes beyond combat gates.

Second archetype, same template

Re-run the Destroyer example's exact milestone shape for a second class with different grind_profile/mob_area values, to prove the template is reusable rather than one-off.
