Quest Mode

Epic 9 Supply Check V1 Single agent No combat

Quest Mode provides a bounded, evidence-driven implementation of the Supply Check quest that begins with Marcela in Kamael Village. The V1 acceptance fixture targets a level-3 Orc Fighter and exercises resource validation, navigation, dialogue, completion evidence, checkpoints, recovery, and operator telemetry.

Current integration boundary Epic 9 ships the quest engine, deterministic replay harness, live gate, persistence, and UI status projection. Quest Mode is not yet a selectable tray profile or an lagent-agent CLI class. Use the focused acceptance test below to validate the implemented flow; do not infer a production launch command from this page.

Validate the shadow replay

From the repository root, run the complete Epic 9 acceptance slice:

macOS / Linux (bash, zsh)

.venv/bin/python -m pytest tests/test_story_9_8_quest_acceptance.py -q

Windows PowerShell

.\.venv\Scripts\python.exe -m pytest tests/test_story_9_8_quest_acceptance.py -q

A passing replay confirms that the fixture completes both objectives without emitting OS mouse or keyboard input, writes a reviewable event trace, and reaches terminal state complete with explicit completion evidence.

What shadow validation authorizes LiveQuestGate allows a live attempt only when the passing replay fingerprint matches the exact canonical resource and profile ID. A changed profile, retry policy, route, dialogue contract, or failed replay closes the gate.

Checkpoints and recovery

Quest progress is persisted to the existing WAL-mode data/sessions.db only after an objective has positive verification. Each checkpoint records the objective index, status, verification source, evidence, and session identity before the next objective begins.

  • A restart may resume from the latest valid, verified checkpoint.
  • An interruption before a checkpoint is ambiguous and requires a safe stop or operator intervention.
  • Death and disconnect recovery use the same lifecycle rules; they do not bypass evidence checks.
  • Failures record the objective index, retry count, reason, and last verified evidence.

Monitor quest status

The existing tray tooltip and status overlay read quest events from the sessions database. During an integrated quest session, they project quest name, current objective, progress, and status without owning or changing quest decisions.

Supply Check · Speak to Marcela · 1/2 · Running
Supply Check · Confirm supply · 2/2 · Complete
Supply Check · Speak to Marcela · 1/2 · Failed · NPC not found

Possible states are running, paused, complete, and failed. New sessions and no-quest sessions clear old quest text; stale events from another session cannot replace the current projection.
