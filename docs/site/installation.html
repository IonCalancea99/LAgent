Installation

These steps get the lagent package and its dependencies installed in an isolated environment. Follow them in order — most historical setup failures in this project came from skipping the virtual environment step.

Prerequisites

ItemDetails
Python3.12.x (requires-python = ">=3.12" in pyproject.toml)
Package managerpip inside a project-local virtual environment
OS for full runtimeWindows (needed for dxcam screen capture, pynput input, pywin32)
OS for dev/test onlymacOS / Linux — install the cross-platform subset and run pytest
GPU driverNVIDIA CUDA-capable driver if you intend to run real inference/training locally
Never install into the system Python macOS ships a PEP 668 "externally-managed-environment" guard. Do not use --break-system-packages or install project dependencies system-wide. Always work inside the project's own virtual environment (.venv).

1. Create and activate a virtual environment

cd /path/to/LAgent
python3.12 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python -m pip install -U pip

Confirm the venv's interpreter is active before continuing:

which python      # should point inside .venv
python --version  # should report 3.12.x

2. Install the package

Install in editable mode so code changes are picked up immediately:

python -m pip install -e .

For development (tests, linting, formatting), install the optional dev extras:

python -m pip install -e ".[dev]"

This pulls in pytest, pytest-cov, black, and ruff in addition to the runtime dependencies declared in pyproject.toml (Pydantic, PyYAML, PyZMQ, structlog, Ultralytics YOLO, MLflow, Pillow, yt-dlp, OpenCV, EasyOCR, dxcam, mss, pynput, pystray, PyQt6).

Use Python 3.12, not a newer interpreter The editable development install skips dxcam and pywin32 correctly on macOS. An existing Python 3.14 environment still fails because the pinned PyZMQ and MLflow/PyArrow ranges do not provide compatible wheels and their source builds fail. If python --version is not 3.12.x, recreate .venv with python3.12 before installing.

3. Platform-specific dependencies

A few dependencies are intentionally platform-restricted. This is expected behavior, not a broken install:

PackagePlatformPurpose
dxcamWindows onlyLow-latency per-window screen capture
pynputCross-platform, but only meaningful for live input simulation on the target Windows clientMouse/keyboard simulation and Recording Mode input capture
pywin32sys_platform == 'win32' onlyWindows API access
mss, opencv-python, easyocr, ultralyticsCross-platformFallback capture, image processing, OCR, YOLO
Working on macOS/Linux With Python 3.12, you can install and run everything except the Windows-only pieces, and the full test suite runs on the cross-platform subset (this mirrors what the project's Dockerfile does — see below). Live capture and simulated input against the real game client require Windows.

4. Alternative: Docker-based setup

The repository ships a Dockerfile that builds a minimal, reproducible test image without the platform-specific packages:

docker build -t lagent-test .
docker run --rm lagent-test

This installs only the cross-platform runtime dependencies plus pytest, then runs the test suite (python -m pytest tests/ -v) as the container's default command. Use this path for repeatable CI-like validation instead of ad hoc local pip attempts.

5. Verify the installation

Run the test suite from inside the activated virtual environment:

PYTHONPATH=. python -m pytest -q

A clean pass confirms the interpreter, package install, and import graph are all consistent. If you see missing-module errors, double-check that:

  • The active interpreter is .venv's Python, not the system one
  • You ran pip install -e . (or .[dev]) after activating the venv
  • You are not trying to install a Windows-only package on macOS/Linux
