Training Pipeline

LAgent's vision and behavior models are produced entirely offline, from your own gameplay recordings and optional YouTube footage. Training is invoked exclusively via the lagent.train CLI — it never co-runs with a live session, since both compete for the same GPU.

Never train during a live session A live Session and a training run must not run concurrently on the same machine. Stop any active session before running python -m lagent.train ….

Review predictions before training The generated prelabeled.json can be imported into Label Studio as prediction suggestions. Correct and submit every task, then train from the reviewed annotations; predictions alone are not used as training labels. The trainer accepts raw Label Studio JSON exports as well as the normalized {"tasks": [...]} form described below.
Use the class-specific labeling guide Before creating a project, open the Label Studio Guide. It contains copy-paste templates for Common, Warlord, Prophet, and Fishing, plus minimum and recommended image counts and a pre-export quality checklist.

1. Recording gameplay

Start an agent process with --record to capture frames and your manual keyboard/mouse input simultaneously, with no interference to normal play:

macOS / Linux (bash, zsh)

python -m lagent.agent --class warlord --record

Windows PowerShell

python -m lagent.agent --class warlord --record

Or use the "Recording Mode" toggle from the tray menu. Recording is mutually exclusive with a live automated session at process launch. Output is written under recordings/.

2a. (Optional) YouTube frame ingestion

Supplement your own recordings with frames extracted from a public video:

macOS / Linux (bash, zsh)

python -m lagent.train ingest --url "<video-url>" --fps 5 --output-dir recordings

Windows PowerShell

python -m lagent.train ingest --url "<video-url>" --fps 5 --output-dir recordings
FlagDefaultDescription
--urlrequiredPublic video URL supported by yt-dlp
--fpsrequiredFrames to extract per second (must be positive)
--output-dirrecordingsWhere extracted frames are written

Ingested frames are indistinguishable from recorded frames once in the label queue — no credentials are required, and downloading uses yt-dlp only.

2b. Auto-prelabeling

Run the current YOLO models over every captured frame to produce a first-pass annotation file in Label Studio import format:

macOS / Linux (bash, zsh)

python -m lagent.train prelabel \
    --recording recordings/<session-folder> \
    --batch-size 32 \
    --confidence-threshold 0.5 \
    --model-root models

Windows PowerShell

python -m lagent.train prelabel `
    --recording recordings\SESSION_FOLDER `
    --batch-size 32 `
    --confidence-threshold 0.5 `
    --model-root models
FlagDefaultDescription
--recordingrequiredPath to a recording directory containing a frames/ subdirectory
--batch-size32Frame inference batch size
--confidence-threshold0.5Minimum detection confidence kept in the output
--model-rootmodelsRoot directory containing <class>/current.pt models

The command writes recordings/<session-folder>/prelabeled.json, which can be imported into Label Studio as prediction suggestions. It requires both frames/ and inputs.jsonl, accepts PNG/JPG/JPEG frames, skips unreadable frames, and overwrites the previous prelabel file atomically. Review and submit the suggestions in Label Studio, then export the corrected annotations for training.

3. Install and start Label Studio

Label Studio is an external application and is not installed by LAgent. Install it in a separate virtual environment so its web-app dependencies cannot change LAgent's runtime environment:

macOS / Linux (bash, zsh)

python3.12 -m venv .label-studio-venv
source .label-studio-venv/bin/activate
python -m pip install -U pip label-studio
LABEL_STUDIO_LOCAL_FILES_SERVING_ENABLED=true \
LABEL_STUDIO_LOCAL_FILES_DOCUMENT_ROOT="$PWD/recordings" \
label-studio start

Windows PowerShell

py -3.12 -m venv .label-studio-venv
.\.label-studio-venv\Scripts\Activate.ps1
python -m pip install -U pip label-studio
$env:LABEL_STUDIO_LOCAL_FILES_SERVING_ENABLED="true"
$env:LABEL_STUDIO_LOCAL_FILES_DOCUMENT_ROOT=(Resolve-Path recordings)
label-studio start

Leave this terminal running and open http://localhost:8080. Create the local account requested on first launch. Local-file serving gives Label Studio read-only browser access beneath recordings/; do not set the document root to your home directory or filesystem root.

4. Create the labeling project

Choose the template for the model family you are training from the Label Studio Guide. Do not combine labels from different model families in one project unless you are intentionally changing the model contract and all downstream consumers.

  1. Click Create Project and name it after one recording and model family, for example fishing-2026-09-29.
  2. Open Labeling Setup, choose Custom Template, and paste the configuration below.
  3. Replace the sample <Label> rows with the exact classes needed by the model family you are training. Label names are case-sensitive training data: use lowercase and do not mix synonyms such as mob, enemy, and monster.
  4. Save the configuration before importing tasks.
<View>
  <Image name="image" value="$image" zoom="true" zoomControl="true"/>
  <RectangleLabels name="tag" toName="image" strokeWidth="2">
    <Label value="mob" background="#D55E00"/>
    <Label value="character" background="#0072B2"/>
    <Label value="loot" background="#009E73"/>
    <Label value="death_screen" background="#CC79A7"/>
  </RectangleLabels>
</View>

Which classes should be labeled?

Train one model family at a time. Start with the smallest vocabulary required by that behavior; extra classes consume labeling time and can reduce quality when examples are sparse.

Model familyCanonical labelsWhat each box means
commonmob, character, loot, death_screenA targetable hostile; the controlled character; a visible loot object; the full death-state panel or stable death indicator.
warlordmob; optionally melee_rangeEvery targetable hostile relevant to combat. Use melee_range only when there is a consistent visible range indicator; otherwise distance is computed from mob boxes.
prophetmob, characterNearby hostiles used for buff-safety checks and the controlled character used as the distance reference.
fishingtension_indicatorThe complete, visible UI indicator that signals fishing tension while the FSM is waiting.
Startup identification (optional)warlord_skill, prophet_skillA stable class-specific skill icon used only when automatic profile identification is required.
ROIs and OCR values are not object labels Do not box health or mana numbers merely because health_bar and mana_bar appear in a profile. Those are fixed profile ROIs read by EasyOCR. Likewise, keyboard and mouse events in inputs.jsonl are metadata, not labels.

5. Import the recording frames

Import the task file, not the images. Dragging a whole frames/ directory into the import dialog sends every image in a single upload request and fails once the batch exceeds Django's file limits, reporting the misleading error You cannot access body after reading from request's data stream. The task file below avoids uploads entirely by pointing Label Studio at frames already on disk.

Generate a Label Studio task file whose image URLs point to the recording directory. Run this from the repository root with LAgent's environment active, replacing the placeholder once:

python - <<'PY'
import json
from pathlib import Path

recording = Path("recordings/<session-folder>")
extensions = {".png", ".jpg", ".jpeg"}
frames = sorted(p for p in (recording / "frames").iterdir()
                if p.is_file() and p.suffix.lower() in extensions)
tasks = [{"data": {"image":
          f"/data/local-files/?d={recording.name}/frames/{frame.name}"}}
         for frame in frames]
(recording / "label-studio-tasks.json").write_text(
    json.dumps(tasks, indent=2), encoding="utf-8")
print(f"Wrote {len(tasks)} tasks")
PY

The wrapper above is for bash/zsh. In Windows PowerShell, use the same Python body between a here-string and pipe it to the active interpreter:

@'
# Paste the Python lines from import json through print(...), without PY.
'@ | python -

In the project, open Data Manager → Import, select recordings/<session-folder>/label-studio-tasks.json, and confirm that the preview shows images. If images are blank, verify that Label Studio was launched from the repository root with both local-file environment variables set and that the session folder name exactly matches the URL after ?d=.

6. Draw and review bounding boxes

  • Draw one rectangle per visible object instance. Repeated mobs require separate boxes.
  • Fit the box tightly around the visible object or indicator; avoid large areas of sky, terrain, neighboring objects, or unrelated UI.
  • Use the same visual boundary in every frame. For example, choose either the mob body or its target frame and apply that choice consistently throughout the project.
  • Label partially occluded objects only when their identity and useful extent are clear. Skip ambiguous fragments instead of guessing.
  • Include difficult valid examples: different backgrounds, animation states, scales, lighting, overlaps, and screen positions.
  • Leave true negative frames empty and submit them. They teach the model when the object is absent. Do not draw a box around the whole frame to represent “none.”
  • Do not label mouse cursors, floating damage text, names, OCR numbers, decorative icons, or objects outside the intended definition.

Review checklist before export

  • Every task is submitted, including empty negative frames; no task remains only a draft.
  • No visible in-scope object is missing and no box contains multiple object instances.
  • Labels use exactly the configured spelling; synonyms and capitalization variants are absent.
  • Boxes stay inside the image and have non-zero width and height.
  • Near-duplicate frames do not dominate the dataset. Keep varied examples when pruning.
  • Both the early and late parts of the chronologically sorted recording contain useful, labeled examples because the trainer uses a deterministic ordered split.

7. Export and normalize labels.json

  1. Click Export in Label Studio.
  2. Select the raw JSON format, not JSON-MIN, COCO, YOLO, or a predictions-only format.
  3. Save the download as recordings/<session-folder>/label-studio-export.json.
  4. Optionally run the normalization command below to keep the raw export and create a wrapped labels.json with frame filenames. The trainer also accepts a raw top-level list and resolves local-file URLs directly.
python - <<'PY'
import json
from pathlib import Path
from urllib.parse import parse_qs, urlparse

recording = Path("recordings/<session-folder>")
tasks = json.loads((recording / "label-studio-export.json").read_text(encoding="utf-8"))
if not isinstance(tasks, list):
    raise SystemExit("Expected Label Studio raw JSON export to be a list")
for task in tasks:
    image = task.get("data", {}).get("image", "")
    query_path = parse_qs(urlparse(image).query).get("d", [image])[0]
    task["data"]["image"] = Path(query_path).name
(recording / "labels.json").write_text(
    json.dumps({"tasks": tasks}, indent=2), encoding="utf-8")
print(f"Wrote labels.json with {len(tasks)} tasks")
PY

For Windows PowerShell, use the same @' ... '@ | python - wrapper shown in the import step, this time with the export-normalization Python body.

The recording directory is ready only when it contains this shape:

recordings/<session-folder>/
├── frames/
│   ├── 000000.png
│   └── ...
├── inputs.jsonl
├── label-studio-export.json  # retained source export
└── labels.json               # normalized input consumed by training
Keep Label Studio percentages unchanged Raw JSON exports store x, y, width, and height as percentages from 0 to 100. The trainer converts those values to YOLO coordinates. Do not convert them to pixels.

8. Model training

macOS / Linux (bash, zsh)

python -m lagent.train train \
    --recording recordings/<session-folder> \
    --model-class warlord \
    --epochs 10 \
    --batch-size 16 \
    --validation-split 0.8 \
    --lr 0.001 \
    --model-root models \
    --mlflow-dir models/.mlflow \
    --mAP-threshold 0.65 \
    --device cuda

Windows PowerShell

python -m lagent.train train `
    --recording recordings\SESSION_FOLDER `
    --model-class warlord `
    --epochs 10 `
    --batch-size 16 `
    --validation-split 0.8 `
    --lr 0.001 `
    --model-root models `
    --mlflow-dir models\.mlflow `
    --mAP-threshold 0.65 `
    --device cuda

Labeling and export troubleshooting

SymptomLikely causeAction
Images are blank in Label StudioLocal-file serving is disabled, the document root is wrong, or ?d= points outside itRestart Label Studio with the documented environment variables and regenerate the task file.
You cannot access body after reading from request's data stream when importing many filesThe bulk file upload exceeded Django's DATA_UPLOAD_MAX_NUMBER_FILES (default 100) or DATA_UPLOAD_MAX_MEMORY_SIZE. The parser aborts mid-stream and the error handler then fails trying to re-read the request body, hiding the real cause.Do not upload frames. Atomic deployment & versioning

If the trained model clears the --mAP-threshold, it is written to models/<class>/current.pt via a temp-write followed by os.replace() — an atomic swap, so a session can never observe a partially-written model file. The GPU Inference Server only loads current.pt at its own startup; it never reloads mid-session. The prior version is not overwritten until the new one is validated, and every run is tracked in the local MLflow directory for comparison and rollback reference.

Target training time A new behavior/vision model should reach functional quality within about 2 hours on the reference hardware envelope (GTX 1070 Ti class GPU, 4–6 GB VRAM during training).
