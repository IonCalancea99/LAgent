Training Pipeline

LAgent's vision and behavior models are produced entirely offline, from your own gameplay recordings and optional YouTube footage. Training is invoked exclusively via the lagent.train CLI — it never co-runs with a live session, since both compete for the same GPU.

Never train during a live session A live Session and a training run must not run concurrently on the same machine. Stop any active session before running python -m lagent.train ….

Training workflow at a glance

1. Record gameplay
→
2. Auto-prelabel
→
3. Correct in Label Studio
→
4. Train / fine-tune
→
5. Atomic deploy

YouTube ingestion feeds the same pipeline at step 1, as an alternative or supplement to your own recordings (e.g. community footage of fishing mechanics).

1. Recording gameplay

Start an agent process with --record to capture frames and your manual keyboard/mouse input simultaneously, with no interference to normal play:

macOS / Linux (bash, zsh)

python -m lagent.agent --class warlord --record

Windows PowerShell

python -m lagent.agent --class warlord --record

Or use the "Recording Mode" toggle from the tray menu. Recording is mutually exclusive with a live automated session at process launch. Output is written under recordings/.

2a. (Optional) YouTube frame ingestion

Supplement your own recordings with frames extracted from a public video:

macOS / Linux (bash, zsh)

python -m lagent.train ingest --url "<video-url>" --fps 5 --output-dir recordings

Windows PowerShell

python -m lagent.train ingest --url "<video-url>" --fps 5 --output-dir recordings
FlagDefaultDescription
--urlrequiredPublic video URL supported by yt-dlp
--fpsrequiredFrames to extract per second (must be positive)
--output-dirrecordingsWhere extracted frames are written

Ingested frames are indistinguishable from recorded frames once in the label queue — no credentials are required, and downloading uses yt-dlp only.

2b. Auto-prelabeling

Run the current YOLO models over every captured frame to produce a first-pass annotation file in Label Studio import format:

macOS / Linux (bash, zsh)

python -m lagent.train prelabel \
    --recording recordings/<session-folder> \
    --batch-size 32 \
    --confidence-threshold 0.5 \
    --model-root models

Windows PowerShell

python -m lagent.train prelabel `
    --recording recordings\SESSION_FOLDER `
    --batch-size 32 `
    --confidence-threshold 0.5 `
    --model-root models
FlagDefaultDescription
--recordingrequiredPath to a recording directory containing a frames/ subdirectory
--batch-size32Frame inference batch size
--confidence-threshold0.5Minimum detection confidence kept in the output
--model-rootmodelsRoot directory containing <class>/current.pt models

Import the resulting annotation file into Label Studio, review, and correct any wrong or missing labels before training.

3. Model training

macOS / Linux (bash, zsh)

python -m lagent.train train \
    --recording recordings/<session-folder> \
    --model-class warlord \
    --epochs 10 \
    --batch-size 16 \
    --validation-split 0.8 \
    --lr 0.001 \
    --model-root models \
    --mlflow-dir models/.mlflow \
    --mAP-threshold 0.65 \
    --device cuda

Windows PowerShell

python -m lagent.train train `
    --recording recordings\SESSION_FOLDER `
    --model-class warlord `
    --epochs 10 `
    --batch-size 16 `
    --validation-split 0.8 `
    --lr 0.001 `
    --model-root models `
    --mlflow-dir models\.mlflow `
    --mAP-threshold 0.65 `
    --device cuda
FlagDefaultDescription
--recordingrequiredDirectory containing frames/ and corrected labels.json
--model-classcommonWhich models/<class>/ directory to train and deploy to
--epochs10Training epochs
--batch-size16Training batch size
--validation-split0.8Train/validation split fraction
--lr0.001Learning rate
--model-rootmodelsRoot directory for model output
--mlflow-dirmodels/.mlflowLocal MLflow tracking directory
--mAP-threshold0.65Minimum mAP50 required before the new model is deployed
--devicecudacuda or cpu

Atomic deployment & versioning

If the trained model clears the --mAP-threshold, it is written to models/<class>/current.pt via a temp-write followed by os.replace() — an atomic swap, so a session can never observe a partially-written model file. The GPU Inference Server only loads current.pt at its own startup; it never reloads mid-session. The prior version is not overwritten until the new one is validated, and every run is tracked in the local MLflow directory for comparison and rollback reference.

Target training time A new behavior/vision model should reach functional quality within about 2 hours on the reference hardware envelope (GTX 1070 Ti class GPU, 4–6 GB VRAM during training).
